# AGENTS.md

Guidance for Codex and other automated contributors working on The Negroni Pony.

## Project Voice

The project should be beautiful, funny, competent, and absurd. Treat the
engineering seriously because that is what makes the joke land.

## Working Rules

- Keep docs practical and buildable.
- Never invent hardware specs, material ratings, dimensions, or safety claims.
  Mark unknowns clearly and preserve open questions.
- Preserve the decision record. Add new decisions with date, status, context,
  options considered, decision, and consequences.
- Treat calibration data as a first-class artifact.
- Update docs when implementation changes.
- Prefer small files and small functions.
- Add tests for firmware logic where practical.
- Keep food-path, alcohol, power, and tool-safety notes visible.
- Scan first and drill last.

## Source-Control Rule

Digital work may be generated by Codex, but Oaktown Labs owns the result.
Every generated change must be reviewed before merge.
Open pull requests ready for review by default. Do not use draft mode unless
Oaktown Labs explicitly asks for a draft.

## Naming Notes

- The project name is The Negroni Pony.
- The removable nostril tube interface is the Nostril Nozzle.
- The large physical pour control may be labeled PONY POUR.

## Change Hygiene

- Keep pull requests scoped to one milestone or one clear task.
- Do not mix unrelated generated media, CAD exports, calibration data, and code
  unless the task explicitly needs them together.
- Prefer plain Markdown for docs unless a richer artifact is required.
